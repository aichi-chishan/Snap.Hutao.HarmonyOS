# 本地业务备份 v2

原实现仅凭 `app` 字段就删除数据，而且遗漏养成、挑战和便笺。v2 先验证版本、完整表清单、字段、账号凭据归属和引用关系，再使用 API14 起的独立 `relationalStore.Transaction` 写入；最低 API24 已覆盖此接口。

## 内容

- 账号及区域、角色绑定；祈愿和成就的完整持久字段；养成项目、材料和库存。
- 三挑战按 UID/区服隔离的新历史，以及无法确认归属、保持原样的旧历史。
- 便笺完整快照、签到缓存、日历和公告缓存。
- 白名单前缀内可迁移偏好，包括首页布局、签到、便笺、养成项目选择。排除设备身份和凭据类偏好。
- 游戏账号 Cookie 单独放在凭据段，文件是明文，导出位置由用户选择。签名材料、云设备会话、下载资源和本地背景媒体不写入 JSON。

## 失败与中断处理

1. 校验失败不写数据库、不删账号、不修改凭据。
2. 在 IMMEDIATE 事务内读取旧账号和下一个 ID，恢复账号使用新 ID；原安全存储条目在提交之前保持不变。
3. 偏好存储先写恢复日志（只有可迁移偏好和本地 ID，没有 Cookie），然后暂存新凭据。
4. 业务表和恢复标记在同一个数据库事务提交。偏好写失败或数据插入失败会回滚数据库并补偿偏好/凭据。
5. 进程中断或提交结果不确定时保留恢复日志，不继续覆盖该日志、不删除可能已提交的新凭据。下次主应用启动在恢复登录前比较数据库标记，选择旧/新偏好并清理对应失效凭据。
6. 日志仍待恢复时拒绝新的导出/还原，并暂停自动便笺刷新。成功恢复后重新装载本地会话，页面主题等建议重启刷新。

数据库和安全存储并非同一种存储介质。以上是持久化恢复协议，不宣称跨介质原生事务。安全资产删除失败可能留下不可见的旧资产；真机上仍需验证系统存储异常、进程强制退出和设备锁定行为。

## v1 兼容

v1 先转换到已验证的 v2 对象；必需段缺失或版本不受支持直接拒绝。仅旧版未包含的养成、库存和挑战历史保留现有内容。旧版账号被覆盖后，旧账号所属便笺/签到快照不会继续冒充新账号数据。

## 回归

`tests/backup-roundtrip.cjs` 执行实际 ArkTS 服务和模型，存储边界使用可注入故障的测试实现。覆盖完整往返、版本/结构/引用错误、凭据保存失败、删除后插入失败、偏好写失败、提交状态不确定、账号 ID 重映射和重启恢复。它不替代设备上的 AssetStoreKit 与 ArkData 验证。
