# UI/UX 优化调研：接近 Windows 的工作流，采用鸿蒙原生视觉

调研日期：2026-10-02（北京时间）。状态：**研究与设计提案，尚未实施**。

本轮按用户要求只补充调研文档。目标仍是 HarmonyOS API24 及以上、phone / tablet / 2in1，保留“除注入外”的功能范围。上一次阶段提交中已经实现的能力不重新列为缺失；旧 `PORTING_PLAN.md` 的云功能排除和完成状态不作为本次结论依据。

配套文档：[视觉与交互规格](UI_UX_SPEC_API24_PLUS.md) · [源码、SDK 与官方资料证据](UI_UX_EVIDENCE_2026-10-02.md) · [已有实现与剩余功能](WORKLOG_2026-10-02.md)。

## 1. 核心结论

建议保留 Windows 的**导航分组、页面命名、命令组织、归档/账号上下文、列表—详情关系和任务顺序**；用鸿蒙组件实现悬浮导航、系统材质、弹性反馈和自适应布局。优先修复状态与任务路径，再统一视觉。

最有价值的优化不是再增加一层模糊，而是以下六件事：

1. **建立同一套语义导航状态。** 当前手机与宽屏共用数字 `currentIndex`，但索引 2 在手机是便笺、在宽屏是成就，索引 3 在手机是“我的”、在宽屏是便笺。尺寸切换存在错页风险。宽屏返回也不是完整历史回退。[E01](UI_UX_EVIDENCE_2026-10-02.md#e01)
2. **把本地数据和在线身份分开。** 祈愿页目前未登录就只显示登录引导；本地归档的查看、文件导入和导出不应被在线登录挡住。Windows 将归档选择与多种数据获取途径放在同一工作流中。[E02](UI_UX_EVIDENCE_2026-10-02.md#e02)
3. **补齐统一命令栏和上下文。** UID、区域、所选存档/计划、期数应该在执行刷新、导入、上传、删除之前可见。减少“去另一页找入口”和操作完成后只有短暂 Toast 的情况。
4. **分别管理两套鸿蒙材质能力。** HDS 的光感接口起于 6.1.0(23)，可作为 API24 的增强路径；ArkUI `uiMaterial` 起于 26.0.0，需要单独保护。当前统一使用 API26 开关的做法过于粗糙。[E10](UI_UX_EVIDENCE_2026-10-02.md#e10)、[E13](UI_UX_EVIDENCE_2026-10-02.md#e13)
5. **把最新光感放到系统支持的位置。** API26 的普通组件在标题栏/底部 TabBar 之外设置光感可能不生效。当前普通 `Scroll` 侧栏不能作为“最新光感已正确呈现”的依据；文字密集卡片应使用稳定、低成本的表面。[E10](UI_UX_EVIDENCE_2026-10-02.md#e10)
6. **先解决可读性和操作可达性。** 资源色计算显示，浅色主色橙与白色对比度约 2.84:1；浅色辅助文字与白底约 3.43:1。许多交互是自定义 `Row/Text/Stack`，还缺少系统化焦点、读屏和大字验证。[E11](UI_UX_EVIDENCE_2026-10-02.md#e11)、[E12](UI_UX_EVIDENCE_2026-10-02.md#e12)

## 3. 应当保留的 Windows 体验

| 维度 | 应当保留 | 鸿蒙上的调整 |
|---|---|---|
| 信息架构 | 主页；工具；周期；数据；通行证/反馈；账号区与设置 | 宽屏继续分组侧栏；手机用统一功能目录承载分组 |
| 功能名称 | 祈愿记录、成就管理、实时便笺、我的角色、养成计划、幻想真境剧诗、幽境危战等 | 同一功能在导航、标题、首页卡片和搜索中保持同名 |
| 页面组织 | 顶部上下文和命令栏，下面页签/过滤器，主体为概览或列表—详情 | 窄屏折叠次要命令至菜单；详情独立进入，返回恢复筛选和位置 |
| 账号与存档 | 服务账号、游戏 UID、祈愿/成就存档、计划是不同对象 | 统一选择器外观，但保留不同对象及其归属，不能用全局 UID 替代全部存档状态 |
| 首页 | 问候、活动/卡池、可配置仪表板、公告的层次；既有七卡和自定义顺序 | 宽屏保留扫描密度；手机重排布局，不删减用户已选卡片 |
| 视觉识别 | 彩色导航/游戏图标、角色立绘、轻透明表面、清晰页签和数据层次 | 系统操作改用可缩放单色图标；材质、弹窗、触控反馈采用鸿蒙实现 |
| 原生差异 | 保留用户目标，例如打开游戏、导出记录、安排提醒 | 用公开启动入口、系统文件选择器、分享、通知/提醒；不仿制无法执行的 Win32 控件 |

不复制 Windows 的像素尺寸、鼠标专属手势、注册表/进程控制或不可实现的安装操作。也不把最新材质是否显现当成功能可用的前提。

## 5. 分模块调研与改进方案

### 5.1 导航与多设备（UX01、UX05、UX06）

Windows `NavigationView` 使用分组菜单、独立账号页脚和 `Frame`；鸿蒙宽屏已接近分组结构，但账号/设置还位于滚动菜单，“胡桃通行证与云”移到了系统组。手机端则把大量工具混在“我的”内；“强敌挑战”和宽屏“幽境危战”不一致。证据：[E01](UI_UX_EVIDENCE_2026-10-02.md#e01)。

推荐宽屏继续“主页/通行证/反馈 → 工具 → 周期 → 数据”，底部固定账号区和设置。反馈先保留真实已有的诊断与 GitHub 问题入口，不伪装成尚未具备的 Windows 云反馈中心。插件/注入入口不出现；背包只有在非注入的手工/UIIF 管理形成完整工作流后才成为独立一级入口。

手机默认建议调整为“主页 / 工具 / 数据 / 我的”四入口，工具页按 Windows 的工具与周期分组；主页提供祈愿、便笺的快捷卡。若保留现有“主页/祈愿/便笺/我的”的高频布局，也必须增加同一份“全部功能”目录。两种布局共享路由定义，不能另写两套功能清单；本提案优先选择前者以提高与 Windows 的对应关系。

用页面标识、对象标识和上下文维护导航：例如 `gacha/archiveId`、`wiki/avatarId`、`challenge/kind/uid/region/scheduleId`。数字索引只属于呈现层。系统返回、键盘返回、顶部返回使用同一规则：先关闭临时浮层，再退出详情，再回前一页面，最后才是应用根节点行为。页签切换与“进入详情”要区分；是否记入返回栈应明确而非偶然取决于使用 `router` 还是内嵌分支。

2in1 保留系统窗口控制与避让区；窗口拖拽只响应标题栏空白区。当前顶栏整体监听移动事件，按钮按压、触控拖动和窗口移动是否冲突需要设备验证。折叠侧栏的图标必须有名称提示与键盘焦点，不能只靠用户记忆彩色图标。

### 5.2 首页与启动游戏（UX16）

首页已有七卡、排序、活动和公告，不需要再重造首页。优化重点是内容优先级、加载稳定和可操作状态：只让首次空白加载显示占位；随后刷新保留旧卡和时间戳；单一卡失败不让整页消失；当前账号切换时不得保留上一账号的个人数据。[E01](UI_UX_EVIDENCE_2026-10-02.md#e01)、[E14](UI_UX_EVIDENCE_2026-10-02.md#e14)

宽屏保留 Windows 的卡池/活动并列、仪表板网格和公告区。手机保持同一逻辑顺序，活动可先给摘要再展开；字体放大时取消固定卡高。启动卡应首先显示“未配置 / 可尝试启动 / 上次失败”等真实状态和单个主按钮；URI、Bundle、Ability 放到设置或高级配置。若尚无厂商确认的游戏入口，展示“配置启动入口”，不能把查询失败描述成游戏未安装。

### 5.3 祈愿记录（UX02、UX07）

现状已具备总览、历史、角色、武器、倒计时五页签以及颂愿切换，不应沿用旧文档“无历史页签”的描述。Windows 还有统计页签、归档下拉、刷新方式菜单、导入导出和云入口。鸿蒙的导入按钮集中在历史区域，且整个主体受登录态控制。[E02](UI_UX_EVIDENCE_2026-10-02.md#e02)

建议固定顶部“祈愿记录 + 存档/UID选择器”，命令区为“刷新▾ / 导入导出 / 云同步 / 更多”。刷新菜单提供可支持的账号获取、手动链接和增量/全量；Windows 浏览器缓存读取在鸿蒙沙盒没有等价来源时不给假入口。全量的说明应是“重新获取接口可返回的记录”，不能承诺恢复服务端已过期历史。

导入路径：选择文件/剪贴板 → 格式检查 → 展示 UID、区域、时间范围、记录数和目标归档 → 执行 → 新增/重复/失败摘要。Windows 的导入对话框支持查看文件元信息与 UID 选择；“写入前影响摘要”是本提案增加的可解释性要求，不冒充 Windows 现状。

刷新保留当前统计，显示当前池与已获取条数；取消按钮作用明确。部分池失败保留已成功内容，并在结果区列出可重试池。登录仅在选择需要凭据的获取方式时触发；已有本地存档、离线导入、导出独立可用。

### 5.4 成就管理（UX08）

Windows 把档案管理、导入/导出、优先未完成、仅委托成就放在命令栏，分类与条目形成主从结构。当前鸿蒙已补 UIAF 完整状态与合并策略，但标题仍是“成就”，多个导入按钮和策略说明常驻顶部，占用窄屏空间。[E03](UI_UX_EVIDENCE_2026-10-02.md#e03)

改为“成就管理 + 档案选择器 + 导入/导出/更多”。宽屏左分类右条目，窄屏用分类选择和筛选弹层。合并策略移入导入预览，用“仅补充新信息 / 用导入值更新 / 替换当前档案”等解释文字配合当前实现的精确规则；不要只展示“惰性/积极”术语。

条目主操作是完成状态，复制 ID/攻略是独立命令。已有四种状态与进度/时间要能查看；普通勾选必须有明确映射，不能把“已完成未领奖”和“已领奖”悄然视为同一数据。建议可撤销的本地切换、批量操作影响数量、无结果时一键清除筛选。

### 5.5 我的角色、百科与养成（UX09、UX17）

当前我的角色和百科已有列表—详情及大量字段；新增组合筛选、缓存、导出不应被漏算。主要差距是加入养成时过早写入：百科当前按 Lv.1→90，零计划自动建默认计划，一个计划直接添加，多计划才弹选择；用户不能在同一步确认目标范围。[E04](UI_UX_EVIDENCE_2026-10-02.md#e04)、[E05](UI_UX_EVIDENCE_2026-10-02.md#e05)

推荐统一“加入养成”编辑器：选择/新建计划 → 核对当前值和数据来源 → 设置目标等级、突破、天赋、武器 → 预览材料变化 → 确认加入。我的角色使用已获取且可验证的当前值；百科值标明“手动填写”，不能把默认值说成玩家真实进度。存在同角色条目时，先说明更新还是新增，不重复计入材料。

养成页从“项目区+大计算表单”调整为 Windows 的“材料清单 / 养成物品 / 材料统计 / 背包物品”结构，计算器作为新建/编辑入口。库存普通入口使用名称搜索、图标和数量步进，材料 ID 放在详情。每行区分需求、持有、可合成、缺口；估算显示世界等级及假设。同步前给出来源、时间和影响，不把计算器余量冒称为游戏全背包。

百科宽屏保持列表与详情、命令栏和角色立绘；详情用简介、属性、技能/命座、材料、故事/语音等稳定分区。窄屏先列表再详情，返回保留筛选和滚动；多条件筛选显示当前选项与结果数。皮肤、体型/所属、缺失技能映射等必须等待元数据补齐，界面不能用猜测值填满。

### 5.6 挑战、便笺、签到、日历、札记（UX10、UX11、UX16）

三类挑战已经有按 UID/区域隔离的历史。Windows 的共同结构是期数列表和详情、业务页内统计；当前鸿蒙较多使用横向期次 Chip 和长页。建议宽屏统一“期数列表 / 战绩详情”，窄屏期数选择后进入详情；头部固定角色、服务器、日期范围和数据来源。[E06](UI_UX_EVIDENCE_2026-10-02.md#e06)

个人战绩与全服统计在视觉和文案上区分；统计应回到深渊/剧诗/祈愿对应页。当前集中在云页的通用指标列表可作为过渡，不是 Windows 图表/搭配卡的最终形态。没有可用 API 或字段时显示区块不可用及原因，不展示模拟排行。

便笺保留多角色卡片与逐角色设置，增加稳定的最后成功时间、手动刷新、失效凭据修复入口。系统通知、代理提醒、Webhook 是不同投递渠道，应分开说明权限和触发条件；“已开启”不能等价于“系统一定会送达”。基于旧快照估算的提醒要标注，返回前台后校准。[E07](UI_UX_EVIDENCE_2026-10-02.md#e07)

签到区分已签到、可签到、验证中、失败和补签确认；日历继续沿服务器日期/首日设置，不改回设备本地日。札记显示月份与环比基准，增加正负号和文本，避免仅用红/绿传达意义。公告详情保留正文阅读、复制和外部打开，返回后恢复公告分类及滚动。[E14](UI_UX_EVIDENCE_2026-10-02.md#e14)

### 5.7 登录、通行证、云同步、备份（UX02、UX12、UX14）

米游社/HoYoLAB 与胡桃通行证继续保持独立身份。入口先选服务/区域，再列当前真正支持的登录方式；手动 Cookie 收进高级入口，普通界面用可理解的登录状态和修复动作，技术诊断才显示协议信息。[E08](UI_UX_EVIDENCE_2026-10-02.md#e08)

当前通行证页把登录、注册、找回、改邮箱、撤销设备和注销放在同一长表单，验证码字段跨任务复用。建议拆成 Windows 对应的独立任务弹窗/页面：登录；注册；找回密码；账号资料；安全与设备；注销。每个任务只出现必要字段，错误贴近对应输入项，发送验证码状态属于该任务，不能串用。

祈愿页内的“云同步”复用通行证会话，呈现所选 UID、本地/云数量、服务状态及实际可用操作。删除分成本地归档、云端记录和退出登录三种范围；确认文案必须带对象和后果。云权限/权益不能由 UI 猜测。

本地备份提供文件摘要、版本、时间、账号/归档数量及覆盖范围预览；含凭据的文件需在导出前明确提示用户保存位置。还原进行中阻止重复提交，失败给出实际恢复结果与后续步骤。这里是在已实现事务和中断恢复基础上补体验，不建议修改备份语义。[E09](UI_UX_EVIDENCE_2026-10-02.md#e09)

### 5.8 设置、反馈与状态反馈（UX13、UX15）

设置分为外观、主页与日历、账号与同步、便笺与通知、数据与备份、高级、关于与反馈。宽屏用分组索引定位，手机进入对应分组；高频选项保持直接可见。技术表述例如“GitHub 直连失败自动走镜像加速”收进说明/诊断，主标题使用“游戏数据更新”。[E09](UI_UX_EVIDENCE_2026-10-02.md#e09)

视觉设置建议“跟随系统/自动、减少效果、关闭动态背景”等可理解选项，附小范围实时预览。明确实际可用级别，不向低算力设备承诺“强制最强”。当前设置显示“关闭”但侧栏材质对象不随该偏好变化，存在关闭不完整的风险，必须统一策略。[E10](UI_UX_EVIDENCE_2026-10-02.md#e10)

所有数据页采用共同状态：首次加载、内容、带旧内容的刷新、有效空结果、筛选无结果、需登录/授权、局部错误、整体错误。关键完成和失败使用可停留的结果区；Toast 只补充短反馈。错误正文说明“发生什么、保留了什么、下一步做什么”，错误码放“详情”。风控验证成功返回原任务，取消结束等待，不让用户重复寻找原按钮。

## 6. 高级视觉的采用方向

采用三层视觉关系：**稳定背景 → 易读的数据表面 → 有限面积的原生悬浮交互层**。Windows 的识别度主要来自结构、图标、数据组织与轻透明质感，不依赖把每个卡片做成玻璃。

| 区域 | 推荐视觉 | 对齐与限制 |
|---|---|---|
| 应用底层 | 单一壁纸/静态封面，主题遮罩 | 保留 Windows 背景个性；窗口底色不透明，避免历史透明缓冲问题 |
| 导航/标题/底部页签 | HDS 或 ArkUI 支持场景的系统材质、轻微形变 | API24 HDS 与 API26 ArkUI 分开决策；可读底色始终有回退 |
| 主内容卡片 | 稳定半透明/实体表面、轻描边或阴影 | 保留 Acrylic 的层次感；不要求整个卡片运行最新光感 |
| 菜单/选择器/弹窗 | 优先原生组件的层级、模态、动效与材质 | 避免手工蒙层丢失返回、焦点和系统材质资格 |
| 选中与按压 | 小范围弹性、指示条连续过渡、清楚选中态 | 沿用既有 Motion 体系；不对表格数字和整页同时大幅缩放 |
| 角色立绘/统计 | 清晰主体、数字优先、限定共享过渡 | 图片不透过文字；图表颜色配文字/符号；避免持续装饰动画 |

具体能力分级、材质开关、尺寸提案、动效与性能验收见[视觉与交互规格](UI_UX_SPEC_API24_PLUS.md)。

## 7. 实施批次与退出条件

| 批次 | 内容 | 完成后应可证明 |
|---|---|---|
| A：路由与状态 | UX01/02，统一术语和上下文模型 | 同一任务在三类设备上位置一致；尺寸切换和返回不丢上下文；离线归档可用 |
| B：组件与视觉基础 | UX03/04/05/13，页面头、命令栏、状态区、表面/材质策略 | API24/26 能力分支正确；主题/大字/读屏基本可用；关闭效果真实生效 |
| C：核心数据流程 | 祈愿、成就、导入导出/备份 | 每个数据动作有目标、进度和明确结果；取消/失败可恢复 |
| D：跨页任务 | 角色/百科→计划、材料库存、账号→便笺、挑战→统计 | 列表、详情、编辑、保存及返回形成闭环，缺失业务能力有真实状态 |

每批先冻结任务路径和验收条目，再改组件；不同时重写全部页面、状态管理范式和数据层。现有回归继续保护账号隔离、导入事务、时期归属与缓存。纯样式提案不添加镜像实现的无意义测试；导航状态、能力开关和写入流程才需要行为回归。
