## 执行顺序

1. **调研**：逐业务域比较上游 Model、Service、ViewModel 和实际入口；产出 `audit-*.md`，列出具体路径与行为差异。
2. **P0 数据和凭据正确性**：限制 Cookie 目的域；备份先验证再写入并回滚；挑战历史按 UID/区服隔离；修复 UIAF 状态、UIGF 时区/UID、养成材料保存、通知边沿和签到天数。
3. **P1 非注入功能补齐**：账号区域及海外接口、有效游戏拉起配置、祈愿/成就互通、养成/材料、挑战持久化、百科/日历与背景功能。云客户端与真实在线服务分别验收。
4. **API 24 兼容与环境**：使用仓库实际 CI 工具链 API 26 编译，最低版本 `6.1.1(24)`；新能力在调用点门控；工具下载校验摘要，安装限定在本工作目录。
5. **验证与交付**：纯逻辑回归、lint、无签名 HAP 构建；真实 API 24 设备、登录账号、后台行为作为独立验收，不用 Node 测试替代 ArkTS 编译或真机证据。提交审阅分支和差距状态。

## 已证实、必须优先解决的差距

| 项目 | 修改前问题 | 验收行为 |
|---|---|---|
| 网络 | 通用 ApiClient 对任意 URL 默认附带当前 Cookie | GitHub、资源镜像、云接口不能收到米哈游凭据 |
| 本地备份 | 仅检查 app 标记即删除数据；漏掉养成、挑战与便笺 | 错误/未来格式拒绝且数据不变；有效备份完整恢复；失败可回滚 |
| 挑战历史 | 仅 schedule_id 主键导致账号互相覆盖 | UID+区服+挑战类型+期数独立；旧无归属历史原样保留 |
| 深渊历史 | 保存外层响应，读取按内层解析 | 重启后历史战绩与在线读取一致 |
| UIAF | 未完成状态误判已完成，进度导出丢失 | 保留状态、进度、时间并正确统计 |
| UIGF | 时区固定0、URL记录未核对UID | 按档案保留时区，禁止串档 |
| 养成 | 材料保存未await，武器/天赋计算不完整 | 保存结束即可完整读取，不能空材料报成功 |
| 便笺通知 | 先覆盖旧快照再比较，派遣人数满误判完成 | 用前一快照判阈值，用派遣实际状态判完成 |
| 签到 | 用月内日期篡改累计天数 | 完全采用服务端实际签到天数 |
| 启动游戏 | 猜测包名/EntryAbility，查询失败均报未安装 | 使用可配置有效 Want/URI，准确显示系统错误 |

## 完成定义与边界

- 排除注入、读取游戏进程内存、修改游戏代码。
- Win32 注册表、Windows 可执行程序下载/修复、跨应用私有目录、进程链不能直接在普通鸿蒙应用等价运行；必须列为平台差异并提供可行替代，不伪造成功。
- 云通行证、云备份、云统计需其运营方仍提供兼容服务；客户端完成不代表服务在线或已通过用户账号验证。
- 不上传或使用真实游戏凭据进行开发测试，不将签名文件、SDK、账户信息写入仓库。
- 完成状态以代码、构建日志和测试证据为准，旧文档中的“全量完成”不作为证据。
