# 挑战、便笺与签到阶段实现（2026-10-02）

用户本轮要求收尾提交，本阶段停止新增功能。这里记录实际实现与验证边界，不把“已有页面”视为全量移植完成。

## 已实现

- 三挑战新记录存入 `challenge_records`，以 `(kind, uid, region, schedule_id)` 隔离。所有 Repo、历史入口、页面 UID 切换已接线；异步旧请求不会覆盖新 UID 的页面数据。旧 `abyss_history`、`role_combat_history`、`hard_challenge_history` 原样保留，因为旧记录没有可证明的归属。
- 深渊统一存 API data 对象，读取兼容旧 envelope；一次刷新保存当期与上期，一期失败保留另一期成功结果。幽境解析并保存接口返回的所有档期；修正官方 `teams` 为扁平角色数组的结构，保留等级、命座和耀金字段，同时兼容历史嵌套结构。
- 三挑战 API 使用显式区服端点、DS salt、请求头，并补齐剧诗/幽境 Cookie 失效重试。海外风控不会误发国内验证请求。幽境增加官方 `hard_challenge/popularity` 人气角色请求和独立错误/重试入口。
- 修复便笺先覆盖快照再读旧值造成通知永远不触发的问题；派遣按实际 `Finished` 状态判断；每日奖励提醒按上游“尚未领取”条件及服务器日期抑制重复。通知归属含 UID，不再因固定 ID 互相覆盖。
- `daily_notes.raw_json` 保存完整 API data，保留魔神任务、参量质变仪 obtained、每日委托 status 及未来字段；旧列兼容读取。追踪角色不会覆盖当前 UID 桌面卡，切 UID 不沿用上一个 UID 的内存快照。
- 多账号追踪刷新传递独立 User，不切全局会话。后台/桌面卡风控直接提示回应用验证；卡片系统更新回调会实际联网刷新。
- 增加用户显式配置的便笺 Webhook；只传 `x-uid` 和便笺 JSON，使用独立 HTTP 请求，不附加 Cookie、DS 或设备身份。转发失败不会抹掉成功更新的本地快照。
- 增加默认关闭的系统代理提醒：按最近快照预测树脂/洞天宝钱阈值、全部派遣、参量质变仪到期时间。使用 API 24 可用的 `reminderAgentManager`，按账号/UID 分组取消和重建。设置改变、取消追踪、删除账号会清理对应提醒；通知授权、设备能力、额度拒绝提供真实错误。模块新增 `ohos.permission.PUBLISH_AGENT_REMINDER`。
- 签到保留真实 `total_sign_day`，今日标记独立保存，漏签不再虚增奖励天数；签到/补签补齐 Token 后才读取 Cookie，已有 Cookie 失效时重试；再次要求验证码不会误报成功。自动签到异常记录冷却，服务器日期支持国服及海外时区。
- 数据库 v6 还按其他实施任务约定加入 `achievement_entries.status`、`cultivate_inventory`、`backup_recovery`。迁移失败回滚并停止，只有重复加列可以兼容跳过，不再在任意 SQL 失败后继续升级版本。

## 验证

`scripts/test-challenge-regressions.cjs` 执行生产 ArkTS 转译代码，外部网络/系统接口使用桩，覆盖：

1. 深渊 data/envelope 两种历史格式及战斗详情保留。
2. 幽境多档期、逐期原始 JSON 往返、官方扁平队伍及历史结构兼容。
3. 三 Repo 在相同期数、不同 UID/区服下的隔离与更新。
4. 真实 SQLite 执行生产迁移：新库、v5 升级、旧无归属历史保留、复合主键、便笺/成就新列及新增表。
5. 漏签后“今日已签”与累计奖励天数独立。
6. 便笺完整 payload 往返、真实通知越阈值/重复抑制、派遣状态、不同 UID 的通知 ID。
7. 代理提醒时间估算、禁用/超上限阈值不安排、取消后重建不累积、系统额度失败向上传递、不清理其他功能的提醒。

已在 Node 24.19.0 + DevEco CLI 所带 TypeScript 下通过。运行示例：

```sh
TYPESCRIPT_PATH=/path/to/typescript/lib/typescript.js node scripts/test-challenge-regressions.cjs
```

这组测试验证模型和业务逻辑，不等同 ArkTS 编译、HAP 安装或系统服务真机测试。最后一轮 SDK 报告的 Kit 导入及重载 Promise lint 阻断已修复；最终构建结果由工程统一构建报告记录。

## 尚未完成或依赖设备验证

- API 24 设备上的安装、登录网络链路、系统卡片、通知/提醒授权与触发尚无真机验收证据。
- 应用被系统回收后不会保持 `setInterval` 实时联网；系统卡片回调受系统调度，代理提醒只按最近快照估算。游戏内消耗、设备时间改变、系统通知策略和服务额度都可能影响提醒，需要刷新校正。
- 尚无 WorkScheduler 后台联网任务或持续后台服务，不宣称与 Windows 常驻任务完全等价。
- 没有把旧无归属挑战历史自动分配给当前账号；显式选择归属的迁移界面尚未完成。全量备份仍保留旧表供后续处理。
- 三挑战尚未完整对齐 Windows 元数据档期空记录导航、所有详情字段/图标和先请求 player index 的预热流程；历史导入/导出目前依赖工程全量备份，未新增专用 Windows SQLite 记录导入器。
- HoYoLAB 人机验证目前提示官方应用验证；没有声称实现完整海外自动验证流程。
- 旅行札记现有在线月份查询和统计继续使用，未新增跨年长期历史数据库、单独导入/导出。上游当前 TravelersDiaryViewModel 本身也只提供在线当月卡片。
- 胡桃云账号、云挑战统计/上传等服务不在本文件所列的已完成范围；本阶段不是“除注入外全量移植完成”。
